### 共有功能对比（默认三方：原生表 / OtherOOP / LuaOOP）

42 项测试只定义一次（实现无关）：参与对比的实现在 `benchmarks/suite/impls/` 下各占**一个适配层文件**，

**新增一个实现＝往 `impls/` 放一个文件，删掉一个实现＝删掉那个文件**，测试文件、入口与适配层机制都不动。

**汇总**（不适用项不参与领先/落后的计数）：

| 列 | 统计 |
|----|------|
| 原生表 | 不适用 0 项（可比 42 项） |
| OtherOOP | OtherOOP 领先 12 项 / LuaOOP 领先 22 项 / 持平 8 项 / 不适用 0 项（可比 42 项） |

**结论**：与 OtherOOP 相比，本框架的实例创建（含继承实例）、构造链、完整生命周期与继承方法调用都更快，且方法查找开销与继承深度解耦——10 层继承方法调用本框架仅 0.052 us/op，OtherOOP 升到 0.557（10.71x 快）；可比 42 项中本框架领先 22 项、落后 12 项、持平 8 项，实例创建 / 继承实例创建快 2.02x / 1.74x、构造链（3 层）快 1.43x、混合操作快 2.00x；COW 成员默认值读取略慢（0.033 vs 0.030，1.10x）；代价集中在**类创建**（多继承 / 属性 / 单例等能力带来的元数据构造成本，相对 OtherOOP 慢 2.68x，单继承子类创建慢 3.15x），只在类定义期付出一次、不进热路径。

> 判定口径：领先 / 落后 / 持平的阈值为 ±0.5%（`oop_benchmark.lua` 内的 `1.005` / `0.995`），对 24 项字段读取与方法调用这类 1%~5% 的差值非常敏感。**本表为 2026-09-27 单次运行的实测值**（`Config.SafeCreate = true` 默认配置）；创建 / 构造类测试项的 run-to-run 波动可达 ±20%，计数会有 ±3 项波动。

### LuaOOP 独有特性

来源：`benchmarks/suite/oop_features_profile.lua`（us/op，表内为 2026-09-27 单次运行实测值）

**属性开销**（以字段读取 0.005 为基准）

| 访问方式 | us/op | 相对字段读取 |
|----------|-------|--------------|
| 字段读取 | 0.005 | 1.0x |
| get 属性读取 | 0.067 | 13.4x |
| opt 属性读取 | 0.070 | 14.0x |
| opt 属性写入 | 0.069 | — |
| set 属性写入 | 0.067 | — |

`get` / `set` / `opt` 的单次访问开销落在**同一档**（0.067~0.070 us/op，约 13.4x~14.0x 字段读取）：
属性加的是"一次元表拦截 + 一次属性函数调用"，与读写方向无关；`opt` 走的是与 `get` / `set` 相同的分派路径，
body 只多一次 `nil == v` 判断。`opt` 的价值在"读写共用一个属性项"（定义面少写一半），不在单次访问更省。

**继承与方法分发**

| 场景 | us/op |
|------|-------|
| 单例缓存命中获取 | 0.187 |
| 多继承 - 第一基类方法 | 0.050 |
| 多继承 - 第二基类方法 | 0.050 |
| 多继承 - `as` 类型检查（3 层） | 0.116 |
| 菱形 - 根类方法（缓存后） | 0.048 |
| 菱形 - 左分支方法 | 0.050 |
| 深层继承 - 3 / 5 / 10 / 20 层方法调用 | 0.054 / 0.057 / 0.053 / 0.053 |

继承深度从 3 层到 20 层，方法调用开销几乎不变（0.054 → 0.053），说明继承链查找已被缓存摊平，与深度解耦。

**热更新与开关**

| 场景 | us/op |
|------|-------|
| 热更新 - 正常方法调用 | 0.058 |

热更新后（稳态）方法调用开销与常态基本一致（0.058 vs 0.056 us/op）：脚本计时已包含失效后的首次重建（发生在预热阶段），重建代价只在失效后的首次访问出现，不进热路径。`SafeCreate` 关闭 pcall 后实例创建提速约 1.2x（0.500 → 0.420 us/op），代价是构造函数抛错时不再被包装。

## 已知的口径说明

- `[11]` 只验证属性读取值正确，不做性能计时：本文件只负责正确性断言，全部性能数值由 `benchmarks/suite/` 出（口径更严，见 `benchmarks/README.md`）。
- `benchmarks/suite/oop_benchmark.lua` 覆盖全部 42 项共有功能，采用 best-of-3 + 每次 GC，N 列并排（默认原生表 / OtherOOP / LuaOOP，每个实现在 `benchmarks/suite/impls/` 下各占一个适配层文件、由入口 `Test(Adapter.discover())` 自动收集，增删文件即可增删列），并额外给出原生表下界与继承深度趋势；缺项机械严格记 `n/a`（取决于适配层声明的能力，默认集合无缺项）。`benchmarks/suite/oop_features_profile.lua` 只测本框架独有能力，无对照。
